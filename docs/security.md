# 信任与部署

SC-EE-3 是自定义协议。本项目中的自动化回归验证覆盖特定实现行为，独立密码协议审计仍待完成。这里的安全边界是持有端点私钥的两台主机及其可信配置。控制主机、应用或任一代理即可接触该端的明文。

## 签发与分发

`init-pki` 生成新的根 CA、中级 CA 和具名客户端、服务端。各角色信任预先配置的中级 CA 证书。运行时直接验证端点与这个信任锚的关系。项目采用具名双向认证，旧匿名模式及其共享签名私钥不再参与握手。

| 目录 | 用途与分发范围 |
| --- | --- |
| `authority/` | 根 CA 和中级 CA 的签名材料。两把 CA 私钥使用提供的口令加密，留在签发方。 |
| `server/` | 服务端私钥、服务端证书和中级 CA 公共证书，仅交给服务端。 |
| `client/` | 客户端私钥、客户端证书和中级 CA 公共证书，仅交给对应客户端。 |

初始化时交互输入签发口令。自动化可设置 `SC_CA_KEY_PASSWORD`。如需加密端点私钥，在签发和相应端点运行时分别设置 `SC_CLIENT_KEY_PASSWORD`、`SC_SERVER_KEY_PASSWORD`。省略端点口令时使用未加密 PEM，凭据目录需由操作系统账户保护。Windows 目录继承父目录 ACL，应选用受控的账户目录。

在远端保留对应角色子目录，例如 `SC_PKI_DIR/client/`。也可以用 `SC_CA_CERT_FILE`、`SC_CLIENT_CERT_FILE`、`SC_CLIENT_KEY_FILE`、`SC_SERVER_CERT_FILE`、`SC_SERVER_KEY_FILE` 指定文件。自定义名称签发后，在两端设置相应的 `SC_SERVER_NAME` 和服务端的 `SC_ALLOWED_CLIENT_NAMES`。独立客户端应有独立身份和私钥。

旧分发包中已发现 CA 和终端私钥。如果部署信任这些材料且包已离开签发方控制，需要在受影响的端点替换信任锚、证书和私钥，并撤下含旧材料的分发包。本目录中的改动只影响新构建。

## 吊销与验证

`SC_CRL_FILE` 指向由相应中级 CA 签名的 PEM 或 DER 吊销列表。设置 `SC_REQUIRE_CRL=1` 后，缺少有效 CRL 时认证失败。部署方负责生成和更新 CRL。

现有测试覆盖证书身份和用途、吊销、记录篡改、重放隔离、序列号、两种 AEAD 套件、本机握手、凭据目录隔离、代理半关闭和停机。构建流程还验证最终分发包。测试结果只对应报告所列版本和环境。连接数限制按监听进程生效，达到上限会拒绝额外连接。


## 2026-11-25 本机验收

本次验收环境为 Windows、CPython 3.13.1、cryptography 50.0.2。使用临时新签发的证书，所有网络用例在本机回环地址运行。

| 检查 | 结果 |
| --- | --- |
| 24 项自动化回归 | 全部通过，包含两个方向的 TCP 半关闭、活动连接和空闲监听器停机 |
| 安装后的五个命令 | 签发、服务端、客户端和两个代理均运行成功，加密回显收到 `echo: hello` |
| 独立进程双代理 | 262,144 字节在客户端半关闭后完整返回 |
| 与原项目 SC-EE-3 互通 | 使用原工作区的握手实现（基于提交 `88d035a`），两种套件均通过旧客户端连接新服务端、新客户端连接旧服务端的握手及数据往返 |
| 分发物 | 从源码包构建 wheel，两种包均通过成员白名单和 PEM 私钥标记检查 |

CI 配置包含 Windows 与 Linux 的 Python 3.10 和 3.13。以上结果来自本机 Windows 验收。
