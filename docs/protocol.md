# SC-EE-3 协议与连接生命周期

## 握手

客户端和服务端预先选择同一套件。每个 TCP 帧使用 4 字节大端长度前缀，帧体上限为 1,000,000 字节。一次握手共用 15 秒网络读写期限。连续的若干帧可以一次写入 TCP，七个协议步骤并不等于七个网络往返。

| 步骤 | 消息与验证 |
| --- | --- |
| 1 | 客户端发送含版本、套件、临时 X25519 公钥及随机数的 ClientHello。服务端检查格式与近期随机数重复。 |
| 2 | 服务端合并发送自己的 Hello、证书和客户端证书请求。客户端校验签发者、角色及期望的 SAN 身份。 |
| 3 | 客户端发送具名证书。服务端校验用途、有效期和允许的客户端名称。 |
| 4 | 双方用临时共享秘密及双方随机数派生握手密钥。服务端传回受 AEAD 保护的种子及四个参与最终派生的字段。 |
| 5 | 客户端以 Ed25519 签署截至当前步骤的握手摘要。 |
| 6 | 服务端验证客户端签名，随后签署已包含客户端签名的新摘要。 |
| 7 | 两端派生双向链密钥，服务端发送加密 ACK。客户端验证 ACK 后才把连接交给应用。 |

握手摘要按线上顺序累计帧体，不含 TCP 长度前缀。双方都在读入对方签名之前保存待验证的摘要。握手证书以明文传输，网络观察者可以看到身份信息、地址、通信时间和密文长度。

## 数据与代理

应用帧体由 4 字节类型、8 字节大端序列号和密文构成。每个方向有独立的链密钥与序列号。一次 HKDF 同时生成当前消息密钥、下条消息的链密钥和填充材料。接收端在 AEAD 和填充都通过验证后才推进状态。

双方把协议版本、套件、会话摘要、方向、帧类型、序列号、密钥世代和外部关联数据纳入认证。当前握手使用世代 0。每条记录的随机填充有长度上限，应用仍可能泄露统计特征。

普通直连保留 SC-EE-3 的 DATA 格式。成对代理在一个方向读到正常 TCP EOF 后发出带序列号的加密 `FIN!`，只关闭该方向的写端。另一个方向继续发送剩余响应。半关闭功能要求两端代理都使用本整理版，旧代理不识别这个扩展。截断、非法记录或认证失败会结束该连接。

监听器在分配工作线程前取得连接名额。停止监听会唤醒空闲的接受循环，并关闭已登记的连接，等待转发线程退出。新发起的出站连接有独立的连接与握手超时。
